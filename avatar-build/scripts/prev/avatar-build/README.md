# Urdu voice avatar — browser handoff

Extract the delivery archive at the root of `openai-fm`. It contains the `public/avatar` web payload and the `avatar-build` source/proof files. No source app files were modified. Blender Studio's actual saved scene is `/project/scene.blend`; the archive's portable copy is `avatar-build/scene.blend`.

## Browser contract

Load `/avatar/avatar.glb` and `/avatar/avatar.json`. Coordinates are metres, right-handed glTF (+Y up, +Z front). Camera fov in the manifest is vertical, in degrees. `bones` maps semantic roles to actual glTF joint node names, including legs, toes and the 30 finger joints. A loader may sanitize the colon in `mixamorig:`; map by glTF node index or the loader's sanitized name rather than renaming the file. Gaze is implemented with the eight eyeLook targets, not with separate eye bones.

The face, eyes, teeth, tongue, brows, and lashes are combined on the `Body` node (`FaceBody` mesh) with separate material primitives. That gives all moving face parts one 67-name target order, without requiring duplicate empty keys on separate accessory meshes. In Three.js, traverse the loaded scene and set each applicable child mesh's `morphTargetInfluences[morphTargetDictionary[name]]`. Do not assume the `Body` group itself is drawable, or drive just its first primitive. `avatar.json` enumerates the actual node and mesh names, morph names, triangle counts, height landmarks, camera and bone map. Preserve initial morph weights for the relaxed resting expression; ease speech weights back to those values rather than leaving the last viseme latched.

`glb-check.json` was generated by decoding the final binary, including sparse target accessors, skin weights and inverse bind matrices. It contains the checksum, metrics, every joint, every embedded image's dimensions, actual posed bounds, per-target and per-material motion, and image difference for two round-trip renders. A target can legitimately have no motion on an unrelated material: a blink doesn't shift a tooth. `jawOpen` does move lower dentition and tongue. `viseme_sil` is a subtle lip closure rather than a dummy key.

## Build order

The build ran in Blender 5.2.4 LTS on Linux with one L40S. `scripts/` contains the actual source stages in functional order (export precedes the proof renders despite the two filenames' numbers). `rebuild-inputs.zip` is a separate archive inside this delivery: it contains the exact MPFB body/rig and skinned/baked checkpoints plus the CC0 fitting hair input used in the early wardrobe stage. Start from these to reproduce the final build without downloading external asset libraries. The two original MPFB human-creation stages and their settings are included as provenance, not required to reconstruct from the supplied checkpoints.

1. Work in a **fresh**, disposable `/project` directory. The scripts intentionally use absolute Linux paths and save `scene.blend`; do not run them over another project. Copy the supplied `avatar-build` directory there, extract `avatar-build/rebuild-inputs.zip` into `/project`, and create `/project/build/tex`, `/project/build/scripts`, `/project/public/avatar`, and `/project/avatar-build/renders` if absent. Put a copy of `rlib.py` in `/project/build/scripts`. Keep `avatar-build/reference/design-sheet.png` and `ortho.jpg` as supplied. System Python requires Pillow, numpy, scipy, OpenCV and MediaPipe 0.10.21. Blender supplies bpy and mathutils.
2. `00_textures.py`, `01_body.py` and `02_skinbake.py` are the historical MPFB base stages; `assets.json` and `face_details.json` are their parameters. The exact results are `build/out/stage1.blend` and `stage2.blend` inside the rebuild inputs. Use those packed checkpoints for the remaining steps.
3. Run `03_textiles.py` in system Python. Run `04_dress.py` in Blender with `stage2.blend` open. Copy its `/project/scene.blend` result to `/project/avatar-build/wardrobe.blend` before continuing.
4. Run `05_landmarks.py` in system Python against the supplied orthographic checkpoint portrait and design sheet. Run `06_refine.py`, `07_finish.py`, then `07c_polish.py` in Blender, starting each from the preceding saved `/project/scene.blend`. Intermediate garment fitting is followed by a restrained applied cloth pass; final animation uses skin weights, not a browser cloth solver. The final hair is the custom centre-part groom; alternate trial hair assets are not used.
5. Run `09_export.py` from the polished scene. It writes `public/avatar/avatar.glb`, `public/avatar/avatar.json` and the final packed `/project/scene.blend`. Run `08_render.py` with Blender arguments `-- all` from that scene, then `-- imported` from a fresh Blender process. Run `10_validate.py` in system Python after both sets of renders. It asserts the size/triangle limits, one skin, 67 active morphs, floor alignment, image limits and absence of decoder compression. The complete production sequence was executed; a separate clean-room replay of this archive was not performed.

## Assets and limits

Real human base, fitting data, photographed skin, eyeballs, teeth, tongue, expression targets and skeleton from MakeHuman / MPFB2. Skin: Cutoff3D Indian Female Skin from the CC0 skin pack. Brows and lashes: Mindfront (CC0). The user's supplied design sheet was used for facial landmark fitting and registered skin-detail baking. This is a reference likeness, not an authenticated identity or a scan. Clothing, hair groom, jewellery, fabric patterns and khussas were modelled for this avatar. The back, hidden anatomy and expression extremes are inferred. The hair cards, regular chiffon pleats, neckline embroidery, shoes and back view are visibly simplified compared with a photograph. Source skin, rig movements and expression assets were adapted; facial performance on a user's actual Urdu speech and arbitrary body animation were not tested. No mobile-browser frame rate is claimed.
